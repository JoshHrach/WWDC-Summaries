# Debugging in Xcode 11
**WWDC19 · Session 412** · [Watch](https://developer.apple.com/videos/play/wwdc2019/412/)

_Platforms:_ iOS 13, iPadOS 13, macOS Catalina 10.15, watchOS 6, tvOS 13

## Overview
Xcode 11 introduces several new debugging capabilities that make it easier to reproduce real-world conditions, catch issues before shipping, and inspect both UIKit and SwiftUI view hierarchies. The session is divided into three parts: Device Conditions and Environment Overrides, Debugging Live Previews, and View Debugger enhancements for SwiftUI and UIKit.

Device Conditions let developers safely simulate elevated thermal states and degraded network conditions from within Xcode — no more trying to physically overheat a device. Environment Overrides provide instant, in-session switching between light/dark mode, Dynamic Type sizes, and accessibility settings without touching system settings. Together they make it practical to test against the full matrix of real-world environments during development. The View Debugger gains first-class SwiftUI support including automatic property discovery via Swift reflection, a `CustomReflectable` protocol for customizing inspector output, and enhanced UIKit inspectors for trait collections, named colors, and symbol images.

## Key Topics

- **Device Conditions** — New in Xcode 11; accessible from the Devices window. Thermal State condition safely raises device thermal state to Fair, Serious, or Critical (device does not physically heat up). Network Link condition simulates high latency, low bandwidth, high packet loss, and slow DNS with modern profiles. Conditions are tied to the Xcode connection and auto-teardown on disconnect. An iOS status bar indicator shows an active condition and tapping it lets the user stop it. **[NEW]**
- **Environment Overrides** — Available while a debug session is active (device, Simulator, or Preview). Overrides interface style (Light/Dark), Dynamic Type text size (all sizes including accessibility), and individual accessibility settings. Only affects the debug process; does not change system settings. **[NEW]**
- **Debugging Live Previews** — Control-click the Play button in the canvas and choose "Debug Preview" to attach the debugger. All standard tools available: breakpoints, variables view, debug navigator, stepping controls.
- **SwiftUI Runtime Issues** — A new category of purple runtime issues generated by system frameworks (including SwiftUI) when APIs are used incorrectly. They appear in the Activity Viewer and Issues Navigator. Do not crash the app but flag important bugs. **[NEW]**
- **Runtime Issue Breakpoint** — A new breakpoint type in Xcode 11 that suspends execution at the point a runtime issue is generated. **[NEW]**
- **SwiftUI View Debugger** — SwiftUI views appear in the navigator and canvas alongside UIKit views. Properties discovered automatically via Swift reflection; `CustomReflectable` protocol lets you expose exactly the data you need. Modifiers currently in effect on a selected view are listed in the inspector. **[NEW]**
- **UIKit View Debugger enhancements** — Support for `UIWindowScene` (multiwindow iOS 13); trait collection info (interface style) in inspector; named color identification (Asset Catalog colors vs. hard-coded); symbol image details (name, symbol configuration, system vs. custom); overhauled constraint inspector with hover-highlight and edge filtering. **[NEW]**

## APIs & Frameworks

### Xcode 11 Debugging Tools **[NEW]**
- Device Conditions — Thermal State (Nominal, Fair, Serious, Critical) via Devices window
- Device Conditions — Network Link (various latency/bandwidth/packet-loss profiles)
- Environment Overrides — interface style, text size, accessibility settings
- SwiftUI Runtime Issues — purple issue indicators in Activity Viewer and Issues Navigator
- Runtime Issue Breakpoint — `Add Breakpoint > Runtime Issue Breakpoint` in Breakpoints Navigator

### SwiftUI (debugging support)
- `CustomReflectable` protocol — implement `customMirror: Mirror` on a `View` to control which properties appear in the Xcode 11 View Debugger inspector **[NEW]**

### UIKit / AppKit
- `UIWindowScene` — now shown in View Debugger navigator; properties (title, activation state) inspectable **[NEW]**
- `UITraitCollection.userInterfaceStyle` — shown per-view in View Debugger inspector **[NEW]**
- Named colors from Asset Catalog — identified as dynamic / adaptive in View Debugger **[NEW]**
- SF Symbols / symbol images — name, symbol configuration, and system-vs-custom shown in inspector **[NEW]**
- Auto Layout constraint inspector — hover-highlight, edge filter, baseline constraint detection **[NEW]**

### ProcessInfo (referenced in thermal handling)
- `ProcessInfo.thermalState` — `.nominal`, `.fair`, `.serious`, `.critical`
- `NSProcessInfoThermalStateDidChangeNotification` — observe thermal state changes

### SwiftUI View Properties (referenced in demo)
- `@State` — mutation inside `body` generates a runtime issue: "Modifying state during view update"
- `HStack(alignment: .firstBaseline)` — correct alignment for mixed text and images

## Code Highlights

Observing and responding to thermal state:

```swift
// In initializer
NotificationCenter.default.addObserver(
    self,
    selector: #selector(thermalStateDidChange),
    name: ProcessInfo.thermalStateDidChangeNotification,
    object: nil
)

func configureSceneFeatures() {
    switch ProcessInfo.processInfo.thermalState {
    case .critical:
        scene.antialiasingMode = .none
        scene.preferredFramesPerSecond = 30
    case .serious:
        scene.antialiasingMode = .none
    default:
        break
    }
}
```

Custom inspector properties in View Debugger:

```swift
struct ProfileView: View, CustomReflectable {
    var customMirror: Mirror {
        Mirror(self, children: [
            "accountStatus": accountStatus,
            "lastLogin": lastLogin,
            "profile": profile
        ])
    }
}
```

Correcting SwiftUI runtime issue (state mutation in body):

```swift
// Wrong — modifying state inside body causes runtime issue
var body: some View {
    loading = false  // "Modifying state during view update"
    return Text("Content")
}

// Correct — mutate state in a callback
weatherFetcher.fetch { data in
    self.loading = false
}
```

## Takeaways

- Use Device Conditions (thermal + network) and Environment Overrides to test the full matrix of real-world conditions without leaving Xcode or touching system settings.
- Pay close attention to purple SwiftUI Runtime Issues — they indicate real bugs (like state mutation in `body`) that won't cause a crash but will cause undefined behavior.
- The View Debugger now provides deep insight into SwiftUI hierarchies: implement `CustomReflectable` to surface the exact properties that matter for debugging your custom views.
- When debugging Previews, keep the preview's source file in a separate pane or window; editing it reopens the preview and starts a new debug session.
