# Bringing People into AR
**WWDC19 · Session 607** · [Watch](https://developer.apple.com/videos/play/wwdc2019/607/)

_Platforms:_ iOS 13, iPadOS 13 (A12 Bionic and later)

## Overview
ARKit 3 introduces two major capabilities that enable real people to be robustly integrated into AR scenes: People Occlusion and Motion Capture. This deep-dive session covers the underlying technology behind both features and shows how developers can adopt them at different levels of abstraction — from a single-line RealityKit configuration to low-level Metal-based custom compositing.

People Occlusion solves the depth-ordering problem between real and virtual content by using a neural network on the A12 chip to generate per-frame segmentation and depth buffers for detected people, enabling virtual objects to correctly pass behind people in the real world. Motion Capture uses machine learning to estimate the 3D pose of a person in real time, providing a 91-joint skeleton that can drive virtual character animations in RealityKit or be consumed directly through ARKit's low-level APIs for analytics, activity recognition, or custom interaction.

## Key Topics

**People Occlusion**
- Problem: previous ARKit overlaid rendered content on top of people regardless of depth
- Solution: two new per-frame buffers on `ARFrame` — `segmentationBuffer` (alpha per pixel) and `estimatedDepthData` (depth per pixel) — generated by a neural network using only the camera image
- Matting step upsamples the low-res neural network output using the full camera image to recover fine edge detail
- Dilated depth generation ensures depth coverage aligns with matte alpha values
- Requires A12 or later; works best indoors; supports hands, feet, and multiple people
- Three adoption paths: RealityKit `ARView` (deepest integration, handles transparency), `ARSCNView` (post-process composite), custom Metal renderer via `ARMatteGenerator`
- Frame semantics: `personSegmentationWithDepth` (occlusion) or `personSegmentation` (weatherman-style, no depth)

**Motion Capture**
- 3D body tracking via `ARBodyTrackingConfiguration` + `ARBodyAnchor`
- 91-joint skeleton with semantically named joints; green joints are ML-estimated, yellow follow parent
- High-level RealityKit API: `bodyTrackedEntity` + `entity.loadBodyTrackedAsync` — drives a character from a USDZ file matching the provided skeleton structure (91-joint naming)
- Low-level ARKit API: `ARBodyAnchor.skeleton` → `ARSkeleton3D` with `jointModelTransforms` and `localTransforms`
- 2D body tracking in image space: `ARFrame.detectedBody` → `ARBody2D` with 16 landmarks in normalized image coordinates
- Use cases: virtual character animation, activity/exercise analysis, gesture recognition, 3D object interaction, semantic image understanding

## APIs & Frameworks

### ARKit 3 (NEW)

**People Occlusion**
- `ARFrame.segmentationBuffer: CVPixelBuffer?` **[NEW]** — per-pixel person segmentation
- `ARFrame.estimatedDepthData: CVPixelBuffer?` **[NEW]** — per-pixel depth for segmented people
- `ARWorldTrackingConfiguration.frameSemantics: ARConfiguration.FrameSemantics` **[NEW]**
- `ARConfiguration.FrameSemantics.personSegmentationWithDepth` **[NEW]** — enables occlusion
- `ARConfiguration.FrameSemantics.personSegmentation` **[NEW]** — segmentation only (no depth)
- `ARMatteGenerator` **[NEW]** — generates matte and dilated depth textures for custom Metal renderers
  - `generateMatte(from:commandBuffer:) -> MTLTexture` **[NEW]**
  - `generateDilatedDepth(from:commandBuffer:) -> MTLTexture` **[NEW]**

**Motion Capture (3D)**
- `ARBodyTrackingConfiguration` **[NEW]** — configuration for body tracking sessions
- `ARBodyAnchor` **[NEW]** — anchor for a detected body; contains `skeleton` and world-space `transform`
- `ARSkeleton3D` **[NEW]** — 3D skeleton geometry with joint transforms
  - `jointModelTransforms: [simd_float4x4]` **[NEW]** — transforms relative to root (hip)
  - `localTransforms: [simd_float4x4]` **[NEW]** — transforms relative to parent joint
  - `modelTransform(for jointName:) -> simd_float4x4?` **[NEW]**
  - `localTransform(for jointName:) -> simd_float4x4?` **[NEW]**
- `ARSkeleton.Definition` **[NEW]** — joint names and parent indices
  - `jointNames: [String]` **[NEW]**
  - `parentIndices: [Int]` **[NEW]**
- `ARSkeleton3D.JointName` **[NEW]** — typed joint name constants (e.g., `.rightHand`, `.leftShoulder`, `.root`)

**Motion Capture (2D)**
- `ARFrame.detectedBody: ARBody2D?` **[NEW]** — 2D body in current frame
- `ARBody2D` **[NEW]** — 2D skeleton in normalized image coordinates
- `ARBody2D.skeleton: ARSkeleton2D` **[NEW]**
- `ARSkeleton2D.jointLandmarks: [simd_float2]` **[NEW]** — normalized (0–1) image coordinates for 16 joints
- `ARBodyAnchor.referenceBody: ARBody2D` **[NEW]** — 2D projection of the 3D body anchor

### RealityKit (NEW)
- `ARView` **[NEW]** — recommended rendering surface; deep people occlusion integration
- `bodyTrackedEntity` **[NEW]** — entity type that binds a USDZ character mesh to a tracked skeleton
- `Entity.loadBodyTrackedAsync(named:) -> LoadRequest<BodyTrackedEntity>` **[NEW]**
- `AnchorEntity(.body)` **[NEW]** — anchor that follows the detected body's position

### ARKit (existing, referenced)
- `ARSCNView` — SceneKit-based AR view; people occlusion added via `frameSemantics` in iOS 13 **[NEW capability]**

## Code Highlights

Enabling people occlusion in RealityKit:
```swift
let config = ARWorldTrackingConfiguration()
if ARWorldTrackingConfiguration.supportsFrameSemantics(.personSegmentationWithDepth) {
    config.frameSemantics = .personSegmentationWithDepth
}
arView.session.run(config)
```

Custom compositor using `ARMatteGenerator`:

Loading a body-tracked character in RealityKit:
```swift
var character: BodyTrackedEntity?
Entity.loadBodyTrackedAsync(named: "robot").sink(
    receiveCompletion: { _ in },
    receiveValue: { entity in
        self.character = entity
        let anchor = AnchorEntity(.body)
        anchor.addChild(entity)
        arView.scene.addAnchor(anchor)
    }
).store(in: &cancellables)
```

## Takeaways
- People Occlusion and Motion Capture both require A12 or later and are enabled via `ARConfiguration.frameSemantics` — check support before configuring.
- `ARView` with RealityKit provides the deepest people occlusion integration (handles transparency and depth correctly); `ARSCNView` uses simpler post-process compositing.
- `ARMatteGenerator` gives full control to custom renderer authors; its `generateMatte` and `generateDilatedDepth` methods produce ready-to-use Metal textures.
- The 91-joint `ARBodyAnchor` skeleton can drive character animation, activity analysis, and 3D interaction; `ARBody2D` provides the 16-joint 2D counterpart for image-space tools.
