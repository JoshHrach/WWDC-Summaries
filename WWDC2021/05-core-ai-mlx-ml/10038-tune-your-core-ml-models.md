# Tune Your Core ML Models
**WWDC21 · Session 10038** · [Watch](https://developer.apple.com/videos/play/wwdc2021/10038/)

_Platforms:_ iOS 15, iPadOS 15, macOS Monterey 12, watchOS 8, tvOS 15

## Overview
This session covers three major advances in Core ML for WWDC21: `MLShapedArray` (a new Swift-native type for multidimensional data), the ML Package format (a new file container for models that supports editable metadata and source-control-friendly diffs), and ML Programs (a new model type with strongly typed intermediate tensors that enables fine-grained control over compute precision).

`MLShapedArray` replaces much of the boilerplate required for `MLMultiArray` by providing value-type semantics, copy-on-write behavior, rich slice syntax, and full conformance to Swift collection protocols. The ML Package format breaks a model's architecture, weights, and metadata into separate files within a macOS package bundle, making metadata editing possible in Xcode and producing minimal diffs in source control.

ML Programs represent neural networks as strongly-typed programs (with blocks, functions, and operations) rather than layer graphs. This allows the Core ML runtime to honor minimum precision constraints during execution — Float16 for Neural Engine / GPU performance, or Float32 for maximum accuracy — without requiring the global `cpuOnly` compute unit override.

## Key Topics

### MLShapedArray
- `MLShapedArray<Scalar>` **[NEW]**: generic, multi-dimensional Swift value type (analogous to `MLMultiArray`)
- Value type with copy-on-write semantics
- Conforms to standard Swift collection protocols (strong typing, no `NSNumber` casting)
- Rich subscript/slice syntax: index a dimension with an `Int` or `Range`
- Initialize with a scalar and shape, from a `MLMultiArray`, or with `MLShapedArray(converting:)`
- Xcode auto-generates `shapedArray` properties alongside existing `MLMultiArray` properties for model outputs
- Requires iOS 15 / macOS 12 deployment target minimum
- `MLMultiArray` ↔ `MLShapedArray` conversion via `init(_ other:)` initializers

### ML Package Format (.mlpackage)
- New **ML Package** format **[NEW]**: macOS package bundle containing separate files for architecture, weights, and metadata
- Editable metadata directly in Xcode (description, author, license, version, custom metadata fields, input/output descriptions) **[NEW]**
- Source-control friendly: metadata stored as `.json` files; only changed files appear in diffs
- Compiled more efficiently than monolithic `.mlmodel` files
- `MLModelDescription` API: all metadata accessible at runtime
- Xcode supports both `.mlmodel` and `.mlpackage` equally (Preview, Utilities, encryption, ML archives)
- Required format for ML Program model type (weights stored separately from architecture)

### ML Programs
- New **ML Program** model type **[NEW]**: represents neural networks as typed programs with ops, blocks, and functions
- Strongly typed intermediate tensors (unlike Neural Networks, where types are inferred at runtime)
- Available starting iOS 15 / macOS Monterey 12
- Must use ML Package format
- Generated by Core ML Converters (coremltools) unified API with `minimum_deployment_target=ct.target.iOS15`
- Default conversion: applies `FP16ComputePrecision` graph pass — casts all Float32 tensors to Float16
- Override to Float32: `compute_precision=ct.precision.FLOAT32` argument in converter
- Mixed precision: specific ops can be set to Float32 while others remain Float16
- Core ML runtime honors tensor types as minimum precision — will not cast below specified type
- Runtime may promote tensors to higher precision if needed
- Float16 ML Programs: eligible for Neural Engine execution (maximum performance/efficiency)
- Float32 ML Programs: execute on GPU + CPU combination (not Neural Engine)
- GPU now supports Float32 ops **[NEW]** (expanded op support for both GPU and CPU)
- ML Program vs. Neural Network comparison:
  - Neural networks: layers + embedded weights + runtime-inferred intermediate types
  - ML Programs: ops + separate weight file + compile-time typed intermediate tensors

### Compute Units and Model Execution
- `MLModelConfiguration.computeUnits`: `.all` (default), `.cpuAndGPU`, `.cpuOnly`
- Neural networks: `cpuOnly` forces Float32 globally; `all` allows automatic partitioning across ANE/GPU/CPU
- ML Programs: precision controlled at conversion time; no need to set `cpuOnly` for Float32 accuracy

## Code Highlights

Initializing and slicing an `MLShapedArray`:
```swift
// 2D shaped array - single line initialization
let shaped = MLShapedArray<Int>(scalars: [1, 2, 3, 4, 5, 6], shape: [2, 3])

// Slice second row
let secondRow = shaped[1]

// Slice rows 0-1, columns 1-2
let subArray = shaped[0...1, 1...2]
```

Using `confidenceShapedArray` from generated model code (iOS 15+ deployment target required):
```swift
let prediction = try model.prediction(input: input)
let confidence = prediction.confidenceShapedArray  // MLShapedArray<Double>
// Find max label per bounding box
for row in confidence.shape[0] ... {
    // Iterate using Swift collection protocols
}
```

Core ML Tools conversion to ML Program (Python):
```python
import coremltools as ct
ml_program = ct.convert(
    source_model_path,
    inputs=[ct.ImageType(shape=(1, 3, 512, 512))],
    minimum_deployment_target=ct.target.iOS15  # Produces ML Program
    # compute_precision=ct.precision.FLOAT32  # Opt into Float32
)
ml_program.save("model.mlpackage")
```

## Takeaways

- Migrate to `MLShapedArray` for all new multidimensional data code; it provides Swift-native ergonomics and is auto-generated in model wrappers for iOS 15+ deployment targets.
- Convert existing `.mlmodel` files to `.mlpackage` in Xcode to enable metadata editing and source-control-friendly diffs; all existing functionality is preserved.
- Use ML Programs (via `minimum_deployment_target=ct.target.iOS15` in coremltools) as the preferred format going forward; Float16 is the default and enables Neural Engine execution.
- If your model is precision-sensitive, convert with `compute_precision=ct.precision.FLOAT32` — this removes the need to set `computeUnits = .cpuOnly` at runtime.
