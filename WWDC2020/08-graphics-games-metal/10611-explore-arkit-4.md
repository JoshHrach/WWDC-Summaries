# Explore ARKit 4
**WWDC20 · Session 10611** · [Watch](https://developer.apple.com/videos/play/wwdc2020/10611/)

_Platforms:_ iOS 14, iPadOS 14 (ARKit 4)

## Overview
ARKit 4 introduces four major additions: Location Anchors (geographic AR anchoring using Apple Maps data and on-device visual localization), the Scene Depth API (dense depth maps from the LiDAR Scanner on iPad Pro), improved raycasting for object placement, and expanded Face Tracking support for more devices. The session covers the API for each feature and explains hardware requirements and geographic availability.

## Key Topics

### Location Anchors — ARGeoTrackingConfiguration **[NEW]**
Location anchors allow placing virtual objects at specific geographic coordinates (latitude, longitude, altitude) anywhere in supported cities. ARKit downloads Apple Maps data for the current area and uses **visual localization** — on-device machine learning comparing camera images against a pre-built feature point map — to determine precise device position relative to real-world geography. No images are sent to Apple's servers; all processing runs on-device.

**Requirements**: Apple A12 Bionic or later + GPS. Supported cities at launch: San Francisco Bay Area, New York, Los Angeles, Chicago, Miami (more added through summer 2020).

**Key classes**:
- `ARGeoTrackingConfiguration` — new session configuration; check `.isSupported` (device) and `.checkAvailability(completionHandler:)` (current location).
- `ARGeoAnchor` — ARAnchor subclass initialized with `CLLocationCoordinate2D` (latitude/longitude); altitude is optional (ARKit fills in ground level from Maps data). Axes: X = east, Z = south, Y = up (right-handed).
- `ARGeoTrackingStatus` — available on `ARFrame` and via `ARSessionObserver`; contains `state` (initializing → localizing → localized, or notAvailable), `stateReason` (e.g., `.devicePointedTooLow`, `.geoDataNotLoaded`), and `accuracy` (`.undetermined`, `.low`, `.medium`, `.high`).
- `ARSession.getGeoLocation(forPoint:completionHandler:)` — converts an ARKit world-space point (e.g., from a raycast) to geographic coordinates.

**Best practices**: only start displaying AR content after reaching the `.localized` state; encourage users to point their device at buildings and stationary structures (not open fields or parking lots); monitor tracking state throughout the session as it can regress.

### Scene Depth API — LiDAR Scanner **[NEW]**
Opens up the depth data underlying the scene geometry feature (from ARKit 3.5) for direct app use. The depth map is generated by fusing LiDAR scanner readings with the wide-angle RGB camera image using on-device ML.

- Enabled via `ARWorldTrackingConfiguration.frameSemantics = .sceneDepth` (after checking `supportsFrameSemantics(.sceneDepth)`).
- Available on every `ARFrame` at 60 Hz via `ARFrame.sceneDepth: ARDepthData?`.
- `ARDepthData` contains:
  - `depthMap: CVPixelBuffer` — each pixel = depth in meters (distance from camera plane). Smaller resolution than the captured image but same aspect ratio.
  - `confidenceMap: CVPixelBuffer` — per-pixel `ARConfidenceLevel` (`.low`, `.medium`, `.high`); reflective and highly absorptive surfaces yield lower confidence.
- When `.personSegmentationWithDepth` is already enabled, `.sceneDepth` is available at no additional power cost on LiDAR-capable devices.
- Common use: unproject depth pixels into 3D world space using `ARCamera` intrinsics, transform, and projection matrix in a Metal vertex shader.

### Improved Raycasting for Object Placement
LiDAR Scanner data automatically improves raycasting accuracy on supported devices — apps already using the raycasting API get the improvement for free. Raycasting now works reliably on featureless surfaces (white walls, etc.).

- `ARView.makeRaycastQuery(from:allowing:alignment:)` → `ARRaycastQuery`
- `ARSession.trackedRaycast(_:updateHandler:)` → continuously updated `ARRaycastResult` as scene understanding evolves (preferred over single-shot `raycast`)
- `ARRaycastQuery.Target`: `.existingPlaneGeometry` (detected planes with shape/size), `.existingPlaneInfinite`, `.estimatedPlane` (from feature points)
- **`hitTest` is deprecated in iOS 14** — migrate to raycasting API.

### Expanded Face Tracking **[NEW]**
Face tracking previously required a TrueDepth camera (iPhone X and later). ARKit 4 extends face tracking to any device with **Apple A12 Bionic or later**, including devices without TrueDepth (e.g., iPhone SE 2020, iPad Air 3rd gen, iPad mini 5th gen).

- `ARFaceAnchor`, `ARFaceGeometry`, blend shapes — all available on all supported devices.
- Depth capture from the face — still requires a TrueDepth camera.

## APIs & Frameworks

### ARKit (iOS 14) **[NEW]**
- `ARGeoTrackingConfiguration` — `.isSupported`, `.checkAvailability(completionHandler:)`, `.run(_:)` on `ARSession`
- `ARGeoAnchor` — `init(name:coordinate:)`, `init(coordinate:altitude:)`, `init(name:coordinate:altitude:)`
- `ARGeoTrackingStatus` — `state: ARGeoTrackingStatus.State`, `stateReason: ARGeoTrackingStatus.StateReason`, `accuracy: ARGeoTrackingStatus.Accuracy`
- `ARFrame.geoTrackingStatus: ARGeoTrackingStatus?`
- `ARSession.getGeoLocation(forPoint:completionHandler:)` — `(CLLocationCoordinate2D, CLLocationDistance, Error?)` callback
- `ARFrame.sceneDepth: ARDepthData?` — enabled by `.sceneDepth` frame semantic
- `ARDepthData` — `depthMap: CVPixelBuffer`, `confidenceMap: CVPixelBuffer`
- `ARConfidenceLevel` — `.low`, `.medium`, `.high`
- `ARConfiguration.FrameSemantics.sceneDepth` — new frame semantic
- `ARWorldTrackingConfiguration.supportsFrameSemantics(_:)` — device capability check
- `ARFaceTrackingConfiguration` — now supported on A12+ devices without TrueDepth
- `ARRaycastQuery` / `ARRaycastResult` / `ARSession.trackedRaycast(_:updateHandler:)` — raycasting (existing; enhanced by LiDAR)
- `ARHitTestResult` / `hitTest(_:types:)` — **deprecated in iOS 14**

### RealityKit (for demos in session)
- `AnchorEntity(anchor:)` — wraps `ARGeoAnchor` for RealityKit scene graph
- Entity positioning (`setOrientation(_:relativeTo:)`, `setPosition(_:relativeTo:)`) relative to geo anchor

## Code Highlights

Checking availability and starting a geo-tracking session:
```swift
guard ARGeoTrackingConfiguration.isSupported else { return }
ARGeoTrackingConfiguration.checkAvailability { available, error in
    guard available else { return }
    let arView = ARView()
    arView.session.run(ARGeoTrackingConfiguration())
}
```

Adding a location anchor:
```swift
let coordinate = CLLocationCoordinate2D(latitude: 37.795313, longitude: -122.393792)
let geoAnchor = ARGeoAnchor(name: "Ferry Building", coordinate: coordinate)
arView.session.add(anchor: geoAnchor)
let geoAnchorEntity = AnchorEntity(anchor: geoAnchor)
geoAnchorEntity.addChild(generateSignEntity())
arView.scene.addAnchor(geoAnchorEntity)
```

Enabling the Depth API:
```swift
let configuration = ARWorldTrackingConfiguration()
if type(of: configuration).supportsFrameSemantics(.sceneDepth) {
    configuration.frameSemantics = .sceneDepth
}
session.run(configuration)

func session(_ session: ARSession, didUpdate frame: ARFrame) {
    guard let depthData = frame.sceneDepth else { return }
    let depthMap = depthData.depthMap
    let confidenceMap = depthData.confidenceMap
}
```

Raycasting for object placement (replacing deprecated hitTest):
```swift
let query = arView.makeRaycastQuery(from: point,
                                    allowing: .estimatedPlane,
                                    alignment: .any)
let raycast = session.trackedRaycast(query) { results in
    // results updated as ARKit's understanding improves
}
```

## Takeaways
- Location anchors enable city-scale AR — virtual objects positioned at GPS coordinates are visually localized on-device using Apple Maps feature data with no cloud uploads.
- Only start rendering AR content at geo-anchors after `ARGeoTrackingStatus.state == .localized`; monitor `stateReason` to guide users toward better localization (point at buildings).
- The Depth API gives direct access to the same 60 Hz depth maps used by scene geometry — use `confidenceMap` to filter low-quality depth pixels for your use case.
- Migrate from `hitTest` (deprecated) to `ARSession.trackedRaycast` for object placement; LiDAR-enhanced raycasting automatically improves results on supported hardware.
- Face tracking now works on all A12+ devices without a TrueDepth camera; depth-based face capture remains TrueDepth-only.
